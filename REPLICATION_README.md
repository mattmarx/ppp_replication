# Patent-Paper Pairs (PPP) — Replication Package

This directory is the self-contained replication package for the PPP dataset
(~500,000 patent-paper pairs, 1976-2023). All active code reads and writes paths
resolved by `ppp_paths.py`: everything inside this directory except the ~79 GB of
public bulk data, which lives in a separate **bulk directory** outside it (see
below). Nothing else outside this directory is required except the runtime services
listed under "External services".

## Directory layout

| Path | Contents |
|---|---|
| `*.ipynb`, `*.py` (root) | Active pipeline code (highest version of each stage) |
| `ppp_paths.py`, `bulk_dir.sh`, `bulk_dir.txt` | Where each data directory is; every notebook and script resolves its roots through them |
| `data/raw/` | ~7 MB of source data that **cannot be re-downloaded**: hand-check CSVs, WoS↔CPC crosswalks, Grok-4 assessments, LLM prompt |
| *bulk directory* (outside this folder; `D:/ppp_data` here, `./data/bulk/` by default) | The ~79 GB `downloadFiles002` fetches from Zenodo: MAG/OpenAlex bulk files, PatentsView `g_*.tsv.zip`, PQR scientist-inventor files. Regenerable, so it is never synced and never in a slim archive |
| `data/conf/` | **Confidential** Web of Science-derived files (read by calculateGovOverlap002) — do not redistribute |
| `data/int/` | Intermediates, fully regenerated by the pipeline. Not synced by Dropbox (`com.dropbox.ignored`); set `TEMP_FILES=<dir>` when invoking `run_pipeline.sh` to store them outside the Dropbox tree entirely (directory junction) |
| `data/fin/` | Final outputs (moved to `../PPP_final_outputs/` by `finalize_replication_data.sh`; recreated empty so the pipeline can be re-run) |
| `woscpcxwalk/` | SNPL WoS↔CPC correspondence tooling (source of the `woscpc*.dta` crosswalks in data/int) |
| `ARCHIVE/` | Not part of replication: the PQR patent-application side branch, LLM model-comparison experiment outputs, and deprecated material (`justUseSimpleRules001` + `finalppps_manual.csv`, SPECTER2 outputs `finalppps_specter2.*`) |

## Execution order

**One-shot run:** `bash run_pipeline.sh` executes steps 2–5 below headlessly in order
(each notebook run in place with outputs saved, logged to `logs/`, stops on first failure;
resume with `--from <notebook.ipynb>`). It preflight-checks the Python env, CUDA, and
Ollama. The manual order, if running notebooks individually:

1. `downloadFiles002.ipynb` — downloads the Zenodo-hosted files listed above into the
   bulk directory (`run_pipeline.sh` triggers this automatically whenever one is missing)
2. `buildBigPossiblePairs003.ipynb` — builds candidate pairs (`data/int/potentialpairswithinwindow.parquet`)
3. Feature notebooks, any order after step 2:
   - `addAuthorsInventors001.ipynb` then `calculateContributorOverlap001.ipynb`
   - `encodePapersPatents002.ipynb` then `calculateContentSimilarity001.ipynb` (GPU strongly recommended)
   - `calculateCitationOverlap001.ipynb`
   - `calculateFieldOverlap001.ipynb`
   - `calculateGovOverlap002.ipynb`
   - `calculateInstitutionOverlap005.ipynb`
   - `calculateSelfPlagiarism004.ipynb` (uses `compute_plagiarism_metrics001.py`; depends on encodePapersPatents002 outputs)
4. `trainRandomForest009.ipynb` — random-forest classification → `data/fin/finalppps.csv`
5. `applyLLMadjustment002.ipynb` — applies LLM assessments → `data/fin/finalpppsadjusted.csv`

Standalone tools:
- `classify_ppp_claude_batch.py` — LLM batch classification (see `BATCH_CLASSIFY_README.md`, `QUICKSTART.md`)
- `merge_ppp_data.py`, `validate_batch_output.py` — LLM-classification support scripts
- `PPPs_with_scientist_inventorsGPU.ipynb` — standalone GPU similarity analysis

## Environment

- `requirements.txt` — notebook pipeline (Python 3.13; reconstructed from the original Windows venv).
  Setup (Windows; Python 3.11+ works): `py -3.11 -m venv .venv313 && .venv313/Scripts/python -m pip install -r requirements.txt`

## data/int is fully regenerable

As of 2026-07-06 all exogenous inputs formerly kept in `data/int/` (the three
`ppp_grok4_*DONOTDELETE*.csv` LLM assessments and the four `woscpc*.dta` crosswalks) live in
`data/raw/`, and the notebooks read them from there. `data/int/` and `data/fin/` can therefore
be deleted wholesale and rebuilt by running the pipeline.

One caveat: `data/int/chunk_1..24_results.{csv,parquet}` are per-chunk checkpoint outputs of the
LLM institution-matching step in calculateInstitutionOverlap005. No code reads them back, so the
pipeline survives their deletion, but they represent substantial local-LLM compute.

## Re-running from scratch

To regenerate the entire dataset from `data/raw` plus the bulk directory:

1. **Prerequisites**
   - Python env: `.venv313` with `requirements.txt` installed. Verify GPU torch:
     `python -c "import torch; print(torch.cuda.is_available())"` — if False, you have the
     CPU-only PyPI wheel; reinstall from the CUDA index:
     `pip install --force-reinstall torch==2.9.1 --index-url https://download.pytorch.org/whl/cu126`.
   - [Ollama](https://ollama.com) running locally with `ollama pull llama3.1:8b`
     (used by calculateInstitutionOverlap005; its `chunk_*_results` checkpoints are regenerated).
   - The sentence-transformer model (`all-MiniLM-L6-v2`) downloads from Hugging Face on first use.
2. **Bulk data**: put a path outside this folder in `bulk_dir.txt` (or set `PPP_BULK_DIR`);
   `run_pipeline.sh` downloads whatever is missing there. Leave both unset to use `./data/bulk/`.
3. **Clear intermediates**: delete the contents of `data/int/` (and `data/fin/` if non-empty).
4. **Run** `bash run_pipeline.sh` (or the notebooks individually in the execution order above).
   The heavy steps are encodePapersPatents002 / calculateContentSimilarity001 (GPU-days) and
   calculateInstitutionOverlap005 (local LLM, days).
5. New outputs land in `data/fin/`. The final output (`finalpppsadjusted.csv`) drops
   `low`-confidence pairs — it contains only `high` and `mid`. (`writeFile` in
   applyLLMadjustment002 cell 1 is already set to `True`.)

## Finalizing the data (one-time)

The data files under `data/` sync from Dropbox (the bulk directory does not — it lives
outside the synced tree). After the synced ones are fully available offline, run:

```bash
bash finalize_replication_data.sh
```

It verifies every required file is hydrated on disk, moves `data/fin/` to
`../PPP_final_outputs/` (so `data/int` and `data/fin` can be deleted and the pipeline re-run
cleanly), and smoke-reads one key input per pipeline stage. It is idempotent — re-run it until
it reports PASS.
